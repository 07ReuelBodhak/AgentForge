## 2. Mechanical vs. Policy Guarantees

To ensure complete architectural transparency, AgentForge V2.4 categorizes all boundaries into mechanical guarantees, prompt/policy guarantees, and platform limitations:

| Boundary / Safeguard | Type | Enforcement Mechanism | Failure Mode Behavior |
| :--- | :--- | :--- | :--- |
| **Parent Application Code Modification** | **Mechanical** | Antigravity `PreToolUse` hook intercepts `write_to_file` & `replace_file_content` targeting app paths | Intercepts call, denies execution, emits `PARENT_BOUNDARY_VIOLATION` + `HARD_STOP` |
| **Parent Test Execution** | **Mechanical** | Antigravity `PreToolUse` hook intercepts `run_command` matching test runners (`pytest`, etc.) | Intercepts call, denies execution, emits `PARENT_BOUNDARY_VIOLATION` + `HARD_STOP` |
| **Disk Persistence Gate** | **Mechanical** | Orchestrator verifies physical existence of files on disk (`view_file` / stat) before dispatching tester | Fails immediately; tester is never dispatched if files are missing from disk |
| **Tool Capability Preflight** | **Mechanical** | Preflight check verifies worker subagents have required tools enabled prior to task assignment | Hard stop on missing write tools; prevents dispatching disarmed workers |
| **7-Step Startup Order** | **Policy / Prompt** | Subagent system prompt and dispatch prompt instruct mandatory sequence (Agent Definition → Skill → Task → Context → Codebase Map → Relevant Files → Work) | Enforced via agent system prompts and operational audit |
| **Coder vs. Tester Separation** | **Policy / Workflow** | Coder prompt restricts execution to syntax checks (`py_compile`); Tester prompt owns functional execution (`pytest`) | Tester rejects tests run by coder; Coder flagged if test suites executed |
| **Lane Serialization** | **Workflow Gate** | Orchestrator tracks `modify_files` overlap and serializes tasks touching shared files | Conflicting tasks forced into sequential execution; parallel-safe tasks run concurrently |
| **Human Prerequisite Gate** | **Workflow Gate** | Orchestrator halts workflow when external credentials or inputs are missing | Hard stop until user provides input; fake credentials strictly prohibited |

### Documented Native Antigravity Limitations
- **Single-Tier Subagent Hierarchy**: In native Antigravity, subagents cannot invoke other subagents (`invoke_subagent` is not exposed to subagents). Therefore, the Parent Antigravity session **must** act as the Manager/Orchestrator. Having an intermediate `manager` subagent that dispatches workers is physically unsupported by the runtime.
- **Hook Scope**: Native hooks operate locally within the active session. The PreToolUse hook guarantees the Parent controller does not bypass the worker delegation boundary.

## 3. Truthful Architecture & 5-Worker Roster

AgentForge V2.4 formalizes the **5-Worker Roster** with write-tool capabilities enabled:

```
                      +-----------------------------+
                      |   Parent Session (Manager)  |
                      |  - Orchestrates Workflow    |

         +---------------------------+---------------------------+
         |                           |                           |
+--------v--------+         +--------v--------+         +--------v--------+
|ContextExtractor|         |  Task Planner   |         |      Coder      |

                                     +---------------------------+
                                     | (Hard Disk Persistence Gate)
         +---------------------------+---------------------------+
         |                                                       |
+--------v--------+                                     +--------v--------+
|  Strict Tester  |                                     |   Browser QA    |
|    (forge_*)    |                                     |    (forge_*)    |
| - Runs pytest   |                                     | - Chrome CDP    |
| - Quality audit |                                     | - Visual check  |
| - Evidence log  |                                     | - UI flows      |
+-----------------+                                     +-----------------+
```

### Roster Definitions:
1. **`forge_context_extractor`**: Reads project specifications, PDF overviews, and manifests; outputs structured `project-context.md`.
2. **`forge_planner`**: Analyzes project context and codebase map; generates atomic task contracts in `tasks/` conforming to `tasks/task-schema.md`.
3. **`forge_coder`**: Implements targeted features, components, and unit test suites; verifies syntax with compilation tools; records updates to `docs/codebase-map.md`.
4. **`forge_strict_tester`**: Audits implementations; executes targeted/related/integration test suites; enforces DRY/complexity/dependency constraints; writes evidence to `evidence/`.
5. **`forge_browser_qa`**: Drives live Chrome browser via CDP; audits dual-stream console/network logs; verifies visual fidelity against Stitch design references.
